ParCoar

An AI-assisted car parking system.

What is ParCoar?

A parking garage simulator
A 3D garage on screen. Cars drive in, park, drive out.
A server that assigns spots
When a car arrives, the server picks which spot it gets.
Signs that guide each car
Overhead boards at every turn show the way. The car follows them.

The garage

Three floors
Stacked on top of each other. Ramps connect them.
480 parking spots
Laid out in rows on each floor. Each spot is one painted rectangle.
Lanes and junctions
Cars drive down lanes, turn at junctions, take ramps between floors.

The problem

You can't see which spots are free
From the entrance, just rows of cars. No way to tell what's open.
So you circle
One row, nothing. Next row, nothing. Half the garage later, you find one.
A spot was empty one floor away
You just couldn't see it.

The idea

The garage knows which spots are free
It tracks every spot in real time.
It picks the closest one for you
Not the closest in a straight line. The closest to actually drive to.
It guides you there turn by turn
Signs at every junction show the way. You just follow them.

The simulator

Cars drive in and get guided to a spot
The server picks the spot. Signs guide the car there turn by turn.
Signs update live
Every junction shows which way to turn, as the car moves.
Built with React, Three.js, Python, WebSocket
Frontend renders the 3D garage. Backend decides where each car goes.

How it works

Frontend renders, backend decides
React + Three.js render the 3D garage, move cars, show signs. Python picks spots, calculates routes, keeps reservations.
WebSocket connects them
Browser sends car positions every 80ms. Server replies with directions. About 12 messages per second each way.
One lot.json, shared by both
Generated once from a few parameters. Frontend uses it for geometry, backend uses it for routing.

The garage as a graph

Everything becomes a node
Lanes, junctions, ramps, spots. Each is a point on a map.
Every connection has a distance
The metres a car drives. A turn costs more than a straight lane.

Driving distance, not straight line

Straight line is misleading
The closest spot as the crow flies can be far to drive to.
You can't cut through cars
Reaching the next row means going around a turn.
So we measure driving distance
That's why we need pathfinding, not just nearest neighbour.

Why Dijkstra

The graph is weighted — a ramp is much longer than an aisle step. That rules out anything that counts hops. We need shortest path by real driving distance.
Algorithm Shortest path? Handles weights? Why for ParCoar
DFS
Depth-first search
 No No
Finds a path, not the shortest. Could send a car on a lap of the whole garage.
BFS
Breadth-first search
 Yes No
Shortest by hop count. A ramp and an aisle step count the same. Wrong for driving distance.
Dijkstra
Weighted shortest path
 Yes Yes
Shortest by real edge cost. Simple, fast on 737 nodes. No heuristic needed.
A*
Heuristic-guided search
 Yes Yes
Same answer as Dijkstra but needs a straight-line heuristic. In a garage you can't drive through floors, so the heuristic is weak. More complexity, no benefit.

Dijkstra's algorithm

A shortest-path algorithm from 1959
The same idea your maps app uses to find a route.
It spreads outward from the start
Visits the nearest unvisited node first. Expands in every direction at once.
Stops when it reaches the goal
The first time it arrives, it has found the shortest path. Guaranteed.

A car's life

1
Car enters the garage
Frontend spawns it at the entry node. Sends its position to the server.
2
Server picks a spot
Dijkstra finds the closest free bay. Reserves it so no other car gets sent there.
3
Route calculated
Second Dijkstra finds the path. Each hop becomes a turn direction: left, right, straight.
4
Car drives, signs update
Frontend moves the car along the path. Signs at every junction show the next turn.
5
Car parks, reservation released
Car reaches the spot. Server marks it occupied, releases the reservation.

Picking a spot

First free spot wins
Dijkstra spreads outward from the car. The first free spot it reaches is the closest one to drive to.
Taken spots are skipped
Occupied and reserved spots are blocked before the search starts. Two cars never get sent to the same spot.
No need to search the whole graph
Dijkstra visits nodes in order of distance. The moment it touches a free slot, that's the answer. Everything further away is ignored.
The spot gets reserved instantly
Before the car even starts moving, the slot is marked reserved. No other car can claim it while this one is en route.

Planning the route

Same Dijkstra, but with a destination
Now we know which spot the car is going to. The search stops the moment it reaches that specific spot.
The path becomes the signs
The output is a list of nodes to drive through. Each junction on that list gets a sign pointing left, right, or straight.
Spots are never shortcuts
A parking spot is a dead end. The search can end in one, but it never passes through one to reach somewhere else.
Route recalculated every 80ms
As the car moves, the frontend sends its new position. The server reruns Dijkstra from there, so the route always starts from where the car actually is.

ParCoar

One map drives both the routing and the 3D scene.
Dijkstra on real driving distance picks the closest free spot and the route to it.
The server decides, the browser drives. They talk twelve times a second.
